01 / Executive Summary

3DGS no reemplaza BIM. Lo complementa con una capa de realidad de alta fidelidad.

La pregunta correcta no es "3D Gaussian Splatting vs. BIM/CAD". Son dos representaciones que resuelven problemas distintos, y el valor de negocio aparece cuando conviven dentro del mismo Digital Twin. Cada tecnología responde una pregunta que las demás no pueden responder por sí solas.

BIM / CAD
¿Qué debería existir?

Intención de diseño, geometría paramétrica, semántica de objetos, relaciones entre elementos, especificaciones y metadata para construcción y fabricación.

LiDAR / Point Cloud
¿Dónde está exactamente?

Metrología: posición espacial medible con tolerancia conocida, base para levantamientos, control dimensional y comparación as-built.

3DGS
¿Qué aspecto tiene la realidad?

Apariencia visual fotorrealista, radiance fields navegables en tiempo real, captura rápida por video sin modelado manual.

AI
¿Qué es esto?

Interpretación semántica: segmentación, detección de objetos, clasificación y vínculo entre geometría capturada y clases de objetos BIM.

01.1La ecuación central del informe

BIM/CAD + LiDAR/Point Cloud + 3DGS + AI → DIGITAL TWIN completo

The future is not 3DGS versus BIM. The future is BIM + 3DGS + AI + Metrology.

01.2Lectura rápida para decisores

  • Para constructoras: 3DGS acelera drásticamente la captura de avance de obra (video en lugar de escaneo dedicado), pero no reemplaza el LiDAR/TLS cuando la medición tiene valor contractual.
  • Para estudios de arquitectura: permite integrar el contexto urbano real (fachadas, vegetación, mobiliario existente) alrededor de un modelo BIM propuesto, sin modelar manualmente el entorno.
  • Para fabricantes: habilita catálogos de producto navegables en 3D a partir de un video de celular, a una fracción del costo de un pipeline de modelado + texturizado tradicional.
  • Para BIM Managers: el punto de fricción real es la interoperabilidad — un Gaussian Splat no es un objeto IFC, y requiere una capa de reconstrucción/segmentación para integrarse al flujo BIM.
  • Para inversores: la oportunidad de mayor valor está en la capa de IA semántica que traduce splats en objetos BIM clasificados — no en la captura en sí, que se está commoditizando.

03.2Integración de contexto

  • Contexto urbano real: manzana completa capturada en minutos, sin modelar cada edificio vecino.
  • Vegetación y mobiliario existente: árboles, veredas y elementos urbanos con apariencia real, algo que el modelado manual casi nunca reproduce fielmente.
  • Fachadas circundantes: textura y materialidad real de los edificios linderos para renders de inserción urbana creíbles.
  • Iluminación: condiciones lumínicas reales del sitio como referencia para estudios de asoleamiento y renders.
  • Reducción de modelado manual: el tiempo de un modelador se redirige del entorno hacia el edificio propuesto.

04.3Qué se puede analizar

  • Avance: comparación volumétrica entre lo construido y lo planificado en el 4D BIM.
  • As-built: documentación visual continua del estado real de la obra, sin depender solo de fotos sueltas.
  • Calidad: inspección remota de terminaciones sin necesidad de una visita presencial para cada verificación.
  • Desviaciones: detección de diferencias entre el diseño y la ejecución antes de que se vuelvan costosas.
  • Instalaciones: seguimiento visual de tendidos eléctricos, sanitarios y de climatización antes de cerrar tabiques.

  • Documentación: registro navegable e inmersivo para auditorías, seguros y disputas contractuales.

06 / Accuracy

La confusión más costosa en la adopción de 3DGS en AEC es tratarlo como reemplazo directo del LiDAR. No lo es, y entender por qué evita errores contractuales.

3DGS — optimizado para

  • Visual appearance
  • Novel view synthesis
  • Visual inspection
  • Immersive visualization

LiDAR — optimizado para

  • Geometric measurement
  • Dimensional inspection
  • Survey

06.2Can 3DGS be used for construction measurements?

La respuesta depende del pipeline completo, no solo del renderizado final. Factores que determinan la escala y precisión de un splat:

  • Escala: 3DGS reconstruye geometría relativa; sin referencia externa no tiene unidades reales.
  • Camera calibration: la calidad intrínseca/extrínseca de cámara condiciona toda la reconstrucción posterior.
  • SfM / SLAM: el paso de Structure-from-Motion o SLAM que genera la nube de puntos inicial y las poses de cámara.
  • GPS / RTK: georreferenciación para anclar la escena a coordenadas reales.
  • Control points: puntos de control topográfico medidos independientemente para calibrar escala y corregir deriva.
  • Depth sensors / LiDAR: aportan restricciones métricas duras que un pipeline solo-cámara no tiene.
  • Registration: alineación entre capturas sucesivas o entre 3DGS y el modelo BIM/point cloud de referencia.
  • Bundle adjustment: optimización conjunta de poses y estructura que reduce el error acumulado.

Es útil separar tres conceptos que suelen mezclarse: visual accuracy (se ve correcto), metric accuracy (las distancias son correctas dentro de una tolerancia conocida) y engineering tolerance (la precisión requerida por una norma o contrato específico). Un splat puede tener altísima visual accuracy y baja metric accuracy simultáneamente.

07 / Performance

Archivos, storage y despliegue

Cada representación trae su propia familia de formatos, y el tamaño final depende de decisiones de compresión que cambian drásticamente el resultado.

07.1Formatos por categoría

BIM

IFC, RVT

CAD

STEP, IGES

Mesh

OBJ, FBX, GLB, USD

Point Cloud

LAS, LAZ, PLY

Gaussian Splat

PLY, SPLAT, SPZ, KSPLAT y formatos propietarios emergentes

El tamaño final de un splat depende de: número de Gaussians, coeficientes de Spherical Harmonics (SH) por Gaussiana, cuantización, pruning (eliminación de Gaussianas de bajo impacto), compresión y niveles de detalle (LOD). No existe todavía un estándar único de la industria para Gaussian Splatting equivalente a lo que IFC es para BIM.

07.2Visual Quality vs Storage (conceptual)

Relación conceptual: 3DGS típicamente logra mayor calidad visual percibida por unidad de almacenamiento que un point cloud denso, aunque menor que un mesh muy optimizado a igual fidelidad geométrica baja.

Los desafíos técnicos transversales son: bandwidth (transferir millones de Gaussianas), GPU memory (mantener la escena en VRAM), alpha blending y sorting (ordenar Gaussianas transparentes por profundidad en tiempo real), streaming y scene partitioning (dividir escenas grandes en tiles cargables bajo demanda).

08 / Interoperability

Blender, Unreal, BIM: un splat no es un objeto IFC

La cadena de herramientas de producción exige puentes explícitos entre representaciones que no fueron diseñadas para hablarse entre sí.

Un Gaussian Splat no es equivalente directamente a IFC, STEP, NURBS ni B-Rep. Moverse entre estas representaciones requiere una capa intermedia explícita:

  • Plugins específicos por motor/software para importar y visualizar splats.
  • Converters que extraen geometría utilizable desde las Gaussianas.
  • Point-cloud extraction como paso intermedio hacia formatos de levantamiento estándar.
  • Mesh reconstruction para obtener superficies compatibles con motores de render tradicionales.
  • USD (OpenUSD) como capa de intercambio de escena entre herramientas heterogéneas.
  • Custom renderers capaces de rasterizar Gaussianas nativamente (WebGL/WebGPU/Vulkan).
  • Semantic AI como puente conceptual entre geometría capturada y clases de objeto BIM.

08.1El rol de los estándares abiertos

IFC

Estándar abierto de buildingSMART para intercambio semántico de modelos BIM entre software.

OpenUSD

Formato de composición de escenas de Pixar, adoptado como capa de intercambio entre pipelines heterogéneos, incluyendo activos de reality capture.

glTF

Formato de Khronos Group para entrega eficiente de mesh y materiales en web y tiempo real.

LAS / LAZ

Estándar de la industria geoespacial para point clouds LiDAR.

E57

Formato vendor-neutral para intercambio de datos de escaneo 3D entre distintos fabricantes de equipos.

STEP

Estándar ISO para intercambio de datos de producto en manufactura y CAD mecánico.

WebGPU

API gráfica moderna del W3C/Khronos que habilita renderizado de alto rendimiento de Gaussianas directamente en el navegador.

No existe hoy un estándar universal consolidado específicamente para Gaussian Splatting equivalente a IFC en BIM; el ecosistema de formatos (PLY, SPLAT, SPZ, KSPLAT, entre otros) sigue evolucionando.

12 / Conclusions

Dos capas de verdad, un mismo Digital Twin

Traditional 3D describes what we designed. Reality Capture describes what actually exists. The next generation of Digital Twins needs both.

3DGS should not replace BIM. It should become a high-fidelity reality layer around BIM.

Para una constructora, un estudio de arquitectura o un fabricante que hoy evalúa dónde invertir, la recomendación práctica es concreta: mantener BIM/CAD como fuente de intención y semántica, incorporar 3DGS como capa de captura rápida y de bajo costo para visualización, seguimiento y documentación, reservar LiDAR/TLS para mediciones con valor contractual, y priorizar la capa de IA semántica como la inversión de mayor apalancamiento a mediano plazo.

Fuentes primarias priorizadas: papers fundacionales, documentación oficial y organizaciones de estandarización.

2023
3D Gaussian Splatting for Real-Time Radiance Field Rendering
Bernhard Kerbl, Georgios Kopanas, Thomas Leimkühler, George Drettakis — ACM Transactions on Graphics, vol. 42, n.º 4 — arxiv.org/abs/2308.04079
Paper fundacional que introduce 3D Gaussian Splatting como representación de radiance fields renderizable en tiempo real.
2020
NeRF: Representing Scenes as Neural Radiance Fields for View Synthesis
Ben Mildenhall, Pratul P. Srinivasan, Matthew Tancik, Jonathan T. Barron, Ravi Ramamoorthi, Ren Ng — ECCV 2020 — arxiv.org/abs/2003.08934
Antecedente directo de los radiance fields neuronales que 3DGS busca superar en velocidad de renderizado manteniendo la calidad visual.
—
COLMAP — Structure-from-Motion and Multi-View Stereo
Johannes L. Schönberger et al., ETH Zürich / proyecto open source — colmap.github.io
Herramienta de referencia académica e industrial para el paso de SfM/calibración de cámaras que precede al entrenamiento de un modelo 3DGS.
—
Industry Foundation Classes (IFC)
buildingSMART International — buildingsmart.org
Estándar abierto de referencia para intercambio semántico de modelos BIM; punto de comparación obligado al hablar de interoperabilidad con 3DGS.
—
OpenUSD — Universal Scene Description
Alliance for OpenUSD / Pixar — openusd.org
Formato de composición de escenas cada vez más usado como capa de intercambio entre pipelines de reality capture, VFX y AEC.
—
glTF — Runtime 3D Asset Delivery Format
Khronos Group — khronos.org/gltf
Estándar abierto para entrega eficiente de assets 3D en web y motores en tiempo real; referencia para interoperabilidad de mesh.
—
WebGPU Specification
W3C GPU for the Web Community Group — w3.org/TR/webgpu
Especificación de la API gráfica que habilita renderizado de alto rendimiento de Gaussian Splats directamente en el navegador.
—
Blender — Documentación oficial
Blender Foundation — docs.blender.org
Referencia para flujos de interoperabilidad entre point clouds, mesh reconstruido desde splats y pipelines de visualización.
—
Unreal Engine — Documentación oficial
Epic Games — dev.epicgames.com/documentation
Motor de referencia para integración de Digital Twins, visualización arquitectónica en tiempo real y experiencias VR/MR en AEC.

Esta lista prioriza fuentes primarias y documentación oficial. Para el estado del arte más reciente en Gaussian Splatting (compresión, escenas dinámicas, streaming), se recomienda revisar directamente arXiv (categoría cs.CV / cs.GR) dado el ritmo de publicación del campo.
